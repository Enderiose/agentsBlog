> **2026-10-26 更新：项目停了。**
>
> 停在 M6。停的原因不是做不下去 —— 161 次提交、572 项测试、43 条教训已经把这个想法该证明的都证明了（里面那套「不让门禁撒谎」的测试方法论，后来直接搬到别的项目里用了）。
> 真正把它按下去的是使用场景：要找东西的人得先相信这套流程会被维护，而它只是我一个人的周末项目。
>
> 代码和文档都留着。下面写的那些规矩，跟这个项目停不停没关系 —— 它们现在已经用在别的地方了。

「我的东西放哪了？」

这个问题在我家每天要发生三次。翻箱倒柜找十分钟，最后发现就在眼前。

`FoundInSec`（秒寻）想做的是：**输入名字，柜子上对应的那一格亮起来。**

听起来像是个小工具。但它成了我耗时最长的项目之一 —— 161 次提交，572 项测试，以及一份 **43 条**的教训簿。

因为做完之后我才发现，这个项目真正难的地方不是"定位"，而是**怎么知道自己写的东西是对的**。

## 它是什么

微信小程序。核心交互只有一步：

1. 拍一张柜子的照片
2. 在照片上描出每一格的框（`rect`），给每格起个名字
3. 之后输入物品名，**对应那一格在照片上高亮**

技术选型刻意保守：

| 决定 | 理由 |
|---|---|
| **原生小程序**，不上 TS | 少一层编译，少一类"编译过了但运行时炸" |
| Vant Weapp **只当组件库**，不当骨架 | 骨架自己控，避免被框架的抽象牵着走 |
| **不用 Taro / uni-app** | 跨端收益为零（只有微信一个端） |
| **不开 Skyline** | 新渲染引擎的风险不值得为这个规模的项目承担 |
| 只收 **CSV** 导入 | 别的一律不做，先跑通一条路 |
| 读路径**不经云函数** | 直接读库，省一次冷启动 |

最特别的一条：**几何计算放在 `geometry.wxs`**。

WXS 是小程序的渲染层脚本 —— 它在渲染层执行，不跨线程通信，所以描格时的实时计算不卡。代价是 WXS 有大量限制（没有完整 ES6、不能调小程序 API），而且**没法在 Node 里直接跑测试**。

于是我做了一件事：**同一份几何逻辑，在 WXS 里跑，也在 Node 里跑**，两边用同一批测试用例断言结果一致。

```js
// .dev/tools/test/geometry.test.js —— 跨端阈值一致性
// 同一组输入，WXS 与 Node 两份实现必须给出相同结果
```

## 架构：把纯函数榨出来

```
miniprogram/
  config.js            小程序端唯一允许出现魔数的地方，每个数字指回一个决策点
  utils/api.js         唯一允许碰 wx.cloud 的文件
  utils/cache.js       只读缓存，永不回写
  components/cell-grid/
    geometry.wxs       几何计算（渲染层执行、可被 vm 单测）
  pages/               home · container · grid · item · search · import · settings

cloudfunctions/
  shared/              零依赖零 IO 纯函数层
    test/              54 项单测
  initUser/            云环境就绪探针
  saveSpace/           建改空间：位置码服务端生成、软删、rect 批量写
```

两条硬约束贯穿始终：

**「唯一入口」原则。** `config.js` 是唯一允许出现魔数的地方；`utils/api.js` 是唯一允许碰 `wx.cloud` 的文件。这不是洁癖，是因为**这两个东西一旦散开，你就再也说不清"这个数字是干什么的"**。

**纯函数层零依赖零 IO。** `cloudfunctions/shared/` 不碰数据库、不碰网络，所以它可以在 Node 里被 54 项单测完整覆盖。云函数里真正需要跑在云上的部分（DB 往返、事务），才留给真机验证。

## 门禁：572 项测试和它的下限守卫

```bash
npm run hooks:install  # 每个 clone 跑一次，把 ci 挂成 pre-commit
npm run ci             # check + test
npm run hooks:status   # core.hooksPath 指哪 —— 没装就等于没门禁
```

当时的状态是 **`check 7/7` · 572 项全绿**（工程与渲染层 397 · 云函数纯函数层 175）。

但数字本身没有意义。真正有价值的是我在这个项目里学到的最贵的一课：

> **一个绿灯但什么都没测的门禁，比没有门禁更糟。**
>
> 它让你把「没测」当成「测过了」。

这条写在教训簿的开头，编号 `L1`。而它下面跟着 11 种不同的"外衣"。

## 会说谎的门禁：11 种形状

这是整个项目最值钱的部分。每条都是**静默的** —— 不报错，只是不再测任何东西。

### L1 · glob 空匹配时 `node --test` 退出码 0

测试目录被挪走、落进 `.gitignore`、或者改了名 —— `node --test` 匹配不到任何文件，**退出码依然是 0**。

CI 显示绿色，实际上一个测试都没跑。

修法：`ci.js` 强制 `MIN_TESTS`，读不到计数就直接报「glob 没匹配到文件」。

### L2 · 扫不到东西的正则 = 一条永远绿的断言

```js
// 一条"检查有没有越界调用 wx.cloud"的扫描
const hits = code.match(/wx\.cloud/g) || []
assert(hits.length === 0)   // 如果正则写错，hits 永远是空的 → 永远通过
```

修法：每条扫描带 `zeroGuard` —— **提取到 0 处即判红**。而且提取器自己也要被断言（并集 ≥ N + 关键项必含）。

### L3 / L4 · 假环境比真环境宽容

这是同一个病的两种形态：

**形状层**：假云编出了真机根本不会返回的 `maxAge` 字段 → 那条 bug 在模拟里全绿，真机才露。

**语义层**：假查询无条件返回节点 → 「页面级查询直接量组件内部」这种写法在模拟里全绿，真机恒量不到。

修法：假环境必须按**真机回包形状**写；回执字段走白名单；假 `fakeQuery()` 照真机语义（非 `>>>` 一律返回空）。

改完那一刻，四条断言**当场全红**。

### L5 · 验证台报假完成

`bindPhoto` 返回 `ok:false`（被拒），但代码**照样写完了 8 个 rect，然后报告"完成"**。

> 这比悬挂更糟：悬挂你至少知道没完。

修法：云函数返回值全过 `must()`，`ok:false` 就地停 + 记账。

### L6 · 探针拿错入口

我读 `analyzeCommand().blocked` 来验证环境闸门，测出了「连 `cat .dev/.env` 都放行」的荒谬结论。

真因：hook 实际走的是 `checkToolCall`，**任何一层命中即拦**。我读的那个字段根本不是真入口。

> **验证工具的调用面必须和被验对象的真实入口一致。**

### L7 · 反向验证时，替换没匹配上

反向验证的流程是：注入一个 bug → 确认门禁变红 → 撤掉 → 确认放行。

但如果**注入的字符串根本没匹配上**，那"变红"就永远不会发生 —— 而我会以为"验证过了"。

最典型的触发：多行注入串在 CRLF 工作树里**必然命中 0 次**。

修法：注入前先确认替换**真的生效**（命中数 == 1）；按目标文件自身 EOL 换算；命中数 ≠ 1 就报假。

### L9 / L10 / L11 · 钩子本身的三重失效

| 编号 | 症状 | 守它的 |
|---|---|---|
| L9 | 钩子被 CRLF 变成 `bad interpreter` → 门禁不报错，只是**不再存在** | `.gitattributes text eol=lf` |
| L10 | 钩子写在 `.git/hooks/` → **换机 / 新 clone 就没门禁** | 钩子入库 + 每 clone `hooks:install` |
| L11 | 判定全绿 **≠** 钩子真挂着 | 接线测试 + 在新树里真跑一次 |

L11 特别阴：pi 只加载 `.pi/extensions/`、信任按绝对路径记、活会话用上次 `/reload` 的模块快照 —— 三种情况都能"全绿"。

### L31 · 门禁读外部工具的输出时，那份输出的形状本身就是环境的一部分

这条我很喜欢，因为它把"环境差异伪装成代码错误"讲透了。

`ci.js` 靠 `node --test` 的汇总行取测试计数，而它只认 **spec reporter** 的 `ℹ tests N`。

实测同一条命令、同样走管道：

- node **24.19.0** → 出 `spec` 格式
- node **22.22.2** → 出 `tap` 格式的 `# tests N`

⇒ 换一个 node 跑 `npm run ci`，两个 suite 全读不到计数，**还报成"glob 没匹配到任何文件"**。

注意方向是错的：真实原因是**形状对不上**，不是测试没被扫到。

修法要两处一起：

1. 钉住 `--test-reporter=spec`，让形状不再随版本漂
2. 解析器两种形状都认

而且这里还有第三层：守它的 `E13` 里那个"真跑一次 `node --test`"必须把 `NODE_TEST_CONTEXT` 从子进程环境里摘掉 —— node 的递归守卫一看这个变量还在就拒绝运行，只在输出里留一句 warning ⇒ 计数同样是 `null`，**看上去和"reporter 形状变了"一模一样**。

又一次方向错误的报错。

## 测量与判据：污染结论的三种方式

教训簿的 B 节换了另一个角度：**不是门禁在撒谎，而是我的测量在撒谎。**

### L15 · 截图不是证据

这条直接推翻了我一轮结论。

开发工具侧**过曝**：纯白占 62–79%，`#f2f3f5` 被削成纯白 ⇒ 框边界与照片白底**不可区分**。

我据此写过一版"照片框 x 80..1170"，**是量错的**，一轮结论作废。

> 几何结论只能来自选择器查询（`spike.measure()`），不能来自看图。

### L13 · 输入样本自己也可能是污染源

横图看不出 EXIF 旋转；无 Exif 段的样本测不到方向。

> **判据先问「这台 / 这张能测到它吗」**，测不到就当场说"测不到"，不要给一个假的"没问题"。

### L14 · "看着不对"通常混着两件事

`FIT` 那些框本来就不贴，而截图又过曝到量不出边界 —— "不贴"里混着"数据"与"渲染"，用眼分不开。

修法：判据退化成**等式**（渲染框 ÷ 照片框 == 存的百分比），并单独设一个**对照组**（均匀网格只答缩放，实验组才答贴合）。

### L12 · 测量工具的命名会污染结论

两轮 spike 容器**同名** ⇒ 进错那个没图的，得到"照片不显示"的假结论，而数据侧其实已经通了。

修法：容器名带会话后缀、`report()` 打容器 id。

### L42 · 交付失败先做对照实验，再归因

这条我很庆幸记了下来。

`send_image_to_wechat` / `send_file_to_wechat` 连续三次回 `❌ 发送失败: prepare failed`（158KB PNG ×2、4KB HTML ×1）。

我据此写成"**服务端对体积有限制**"，并准备把 PNG 压到 45KB 交差。

**一测就翻**：

- 先发一张 178 字节的 PNG ⇒ ✅
- 45KB ⇒ ✅
- **最后把那张 158KB 原图重发 ⇒ ✅**

真因 = **桥接刚启动的那几分钟媒体通道还没就绪**（同一条命令 22:41 报「桥接未启动」、22:47 起全部成功），与体积 / 中文文件名 / 图片与文件两条通道**都无关**。

两条教训：

1. 交付失败先跑**一个极小样本**做对照（178B 图就是这条通道的探针），别拿"能自圆其说的理论"当结论
2. 先看**失败的时间戳**（同一命令 6 分钟内从"未启动"变成功 ⇒ 通道状态问题，等一会比改产物划算）

附带事实：`prepare failed` 在扩展源码里 grep 不到 —— 它是**服务端返回的 `errmsg`** ⇒ 本地读代码定位不到根因，只能靠对照实验。

### L43 · 截图工具的"布局视口"不一定等于你指定的截图尺寸

```bash
chrome --headless=new --window-size=430,610 --screenshot=out.png
```

产出的 PNG **确实是 430 宽**（×2 = 860），但页面**布局用的是 747 宽的视口** ⇒ 右侧 317px 被裁掉，用户看到的是文字从中间断开。

两条证据（都不靠眼睛）：

1. 往页面右上角插一个 `position:fixed;right:0` 的红块 ⇒ 解 PNG 数红色像素 = **0**
2. `dump-dom` 读 `clientWidth` = **747**

而且 —— **我自己把查错的路堵上了**：量高度时我写了 `html,body{width:430px;overflow-x:hidden}`，这个 `overflow-x:hidden` 正好让横向溢出**量不出来**。

三条教训：

1. 要断"图没被裁"，用**四边余量**（解 PNG 数墨水像素的 `minX/maxX/minY/maxY`，任一边贴边就是裁了）
2. 量具不要加会改变被测行为的属性（`overflow:hidden` / `display:none` / 固定宽高都是）
3. 要固定版面宽，就在**截图专用的副本里把宽度钉死**，不要指望 `--window-size` 同时管布局

## 那些"不是代码问题"的坑

### L40 · 注释里写 Markdown 粗体 + 路径，会把块注释提前闭合

```js
/** … 单价按 **/kg** 算 … */
```

里面的 `**/` 就是 `*/` —— 注释当场结束，后面那行中文变成**代码**。

`SyntaxError: Invalid or unexpected token`。

`node --check` 立刻能报，但**我是在跑测试时才发现的**（改完只跑了服务端那一侧）。

> 教训：改完客户端文件就当场 `node --check` 一遍。

### L39 · console 里的报错不一定属于你

真机日志里那条 `backgroundfetch privacy fail … private_getBackgroundFetchData:fail` 出自 `WAServiceMainContext.js`（框架启动时调的**私有**接口），与我们的代码无关 —— 全仓 `grep -i backgroundfetch` **零引用**。

它在两轮测试里各出现一次，两次都没坏任何事，但两次都有人（我）想"顺手修一下"。

> 看到报错先问三件：**它出自哪个文件 / 在谁的调用栈里 / 有没有对应的功能症状**。
> 三条都指不到我们，就记档并**不写代码** —— 为平台噪音加 `try/catch` 只会掩盖真问题。

### L16 · "我说了" ≠ "你拿到了"

微信桥接按 800 字符分片，21KB 脚本经过聊天必然腰斩。

> **交付渠道本身也要验** ⇒ 长脚本走文件 / 本机路径；贴给用户的 js 先 `node --check`。

### L32 · 被超时打断的 git 命令会留下"半完成的维护动作"

这条差点毁掉整个仓库。

我把 `git fetch cnb --prune` 放进一个 **120 秒超时**里，fetch 触发的 `gc --auto` 跑到一半被 SIGTERM：

结果 **`.git/refs/` 与 `.git/worktrees/` 整个消失**、`multi-pack-index` 指向一个已被删掉的 pack、三棵 worktree 全部变成"不是 git 仓库"。

**pack 本身是好的**（`verify-pack` ok、历史与 diff 都读得出）。

恢复法（全部只用 reflog 与已知 SHA，**不碰网络**）：

1. 从 `.git/logs/refs/**` 每支的最后一行取回各分支尖端，**手写** `refs/heads/*` 与 `refs/remotes/*`
2. 手写 `.git/worktrees/<id>/{gitdir,commondir,HEAD}` —— `git worktree repair` 在这时候**用不了**，它要求 worktree 的 `.git` 文件先能指到一个**存在**的 gitdir
3. 每棵树 `git reset`（mixed）重建索引（工作区文件一个不动）
4. 把坏掉的 `multi-pack-index` 挪走再 `git multi-pack-index write`

> **在 agent 环境里跑会触发 gc 的 git 命令（`fetch` / `commit` / `merge` / `push`），要么 `-c gc.auto=0`，要么给足超时 —— 别用"到点就杀"。**
>
> "到点就杀"在 git 上不是"这次没跑"，而是"**跑了一半**"，而半完成的 gc 是**破坏性**的。

### L33 · "环境差异"可以细到"哪一块盘"

`L32` 的续集。三棵树 `git status -sb` 全变成 `[gone]`，第一反应是"gc 又删了引用"，于是 `git update-ref` 重建 —— **退出码 0、`find` 看不到、`show-ref` 也没有**。

我当场判成"写进去了、被后续操作删掉了"。**那个判断是错的**：当时我在 worktree 的 `.git`（那是个**文件**，内容是 `gitdir: …`）里 `find`，必然报 "Not a directory"。

> **读数错误犯在"取证工具"上，等于这一轮什么都没测。**

把范围一层层钉死才看清：**C 盘**同一命令正常、bash/Node 在 D 盘建目录正常、一层 ref 正常而两层才失败 ⇒ 只有 **git.exe + D 盘 + 需建中间目录**这一个组合坏，**远端侧完好**。

两条：

1. 取证之前先确认**工具自己站对了地方**
2. 定位环境问题要**换维度做对照**（换盘 / 换程序 / 换深度）—— 换一个维度就少一轮瞎猜

更硬的一句：它不是"建不出来"，是"**已经有的也会被删**"—— `git push origin dev` 报成功、远端真收到了，而本地 `refs/remotes/origin/` 当场变空。

> 凡是"环境把某个动作变成每轮都要手工补一遍"的，**别只修一次就走人**（下次一定忘），要么写进流程清单，要么做个工具。

## 三条元规则

教训簿最后收敛成三条，所有条目都从它们长出来：

1. **每条新护栏都要双向反向验证**：注入 → 确认变红 → 撤掉 → 确认放行；**注入前先确认替换真的生效**。
2. **事实要查文档 / 读字节 / 看回包**，不凭记忆写；未验的假设挂"待核实"，不当默认同意。
3. **测不到的三样要明着说**：WXML 能否编译、视觉是否成立、真实延迟 —— 只有用户能判，标 🟡 直到他亲口确认。

第 3 条最反直觉，也最难做到。Agent 天然倾向于给出"看起来完整"的结论。**说"我测不到这个"，需要主动对抗这种倾向。**

而第 1 条后来被做成了可执行的东西：

```
.dev/tools/test/mutation-runner.js
```

每条注入是**一行数据**，`why` 必须指回教训编号，`npm run mutation` 逐条真跑（注入 → 断言目标护栏变红 → 逐字节还原）。

**第一次跑就抓到 5 条假的**（3 条注入串没匹配上、1 条注入后没变红、1 条重复命中）—— 它们此前都"看起来反向验证过了"。

## 文档分工：五个文件各回各家

这个项目的文档结构后来被我搬到了所有项目上：

| 文件 | 装什么 | 更新频率 |
|---|---|---|
| `specs/SPEC.md` | 当前有效规则：八条硬不变式、技术选型、禁区、护栏 | 改行为时 |
| `plan.md` | 实施计划：M0→M6，**每项带可验等式** | 进度变化时 |
| `handoff.md` | 现在到哪了、卡在哪、下一步 | 每轮 |
| `lessons.md` | **教训簿** `L1`-`L43`，只追加 | 一年几次 |
| `specs/decisions/facts.md` | **事实表** `F1`-`F58`：永久事实 + 守它的那条 | 随发现追加 |

关键认识：**教训是过程沉淀，一年只改几次；状态每轮都刷。**

它们混在一起的时候，`handoff.md` 里"教训"和"为什么信得过"两块占 28 行却一年只改几次，**每轮都要把状态埋掉一次**。

拆开之后，`handoff.md` 只装状态，读起来快得多。

而 `handoff.md` 本身也改过规矩：

> **只增不压**：旧内容**不允许**压缩、改写、删除；新信息**追加**到对应小节。
>
> 为什么改：原先它只装"到哪了/卡在哪"，目标 ≤60 行 ⇒ 每轮都要把上下文压掉一次，新 session 接手时**关键背景已经丢了**。

编号成了沟通语言：`D` 决策 · `T` 技术决策 · `G` 全局约束 · `E` 门禁项 · `F` 事实 · `L` 教训 · `M` 注入。用户提「D16 改成…」「F25 怎么回事」要能定位到那一行。

## 回头看

这个项目教会我的东西，和"做一个小程序"没什么关系。

真正的收获是这一句：

> **绿灯不等于测过了。**

而它下面跟着一长串具体形状：glob 空匹配、正则扫不到东西、假环境比真环境宽容、验证台报假完成、探针拿错入口、注入没匹配上、钩子被 CRLF 弄坏、reporter 格式随 node 版本变……

这些坑有一个共同点：**它们全都不会报错。**

它们只会让你安心。

所以这个项目最后长出来的不是功能，是一套**对抗"安心"的机制**：`MIN_TESTS` 下限守卫、`zeroGuard`、mutation-runner 逐条真跑、教训簿、事实表。

以及一条最难做到的规则：

> **测不到的东西，要明着说测不到。**
