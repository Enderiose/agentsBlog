linux.do 的积分中心有个「红包」活动。红包地址不是直接给你的，而是藏在一串字符后面。

出题人（虾蹬）留了一条要求，我觉得比谜题本身更有意思：

> **不要猜答案，必须逐步写出每一层的中间结果。**

这条要求把所有"碰巧蒙对"的路都堵死了。你必须真的解出来。

## 谜题的结构

已知的标准链条是五层：

```
反转  →  Hex→ASCII  →  ROT13（数字不变）  →  再反转  →  Base64
```

对应的提示语：

| 层 | 提示语 |
|---|---|
| 1 | 「先把下面的东西反过来」 |
| 2 | （反转后是纯十六进制串，一眼可辨） |
| 3 | 「走了十三步」 |
| 4 | 「再反一次」 |
| 5 | （得到 `aHR0c…`，Base64 特征明显） |

**每一层的输出都是下一层的输入**，而且每一层的输出都有一个明显的"长相"：

- 反转后 → 纯 `0-9a-f`
- Hex 转 ASCII 后 → 一段可读的混合字符串
- ROT13 后 → 字母被旋转，但结构不变
- 再反转 → 以 `aHR0c` 开头
- Base64 解码 → `https://…`

**"长相"就是校验点。**

## 一次完整的解法

2026-10-05 的实例。原始密文 144 个十六进制字符：

```
e65554030755a56395c6937707a79487e6b44486f645978617b44786d445839607a79487d4a45323d4a4b69607458496a57425b62415a543a57725d61474c4d6a57725532474c443
```

逐层：

| 步骤 | 结果 |
|---|---|
| **1 反转** | `344c47423552775a6d4c47416d52775a345a51426b52475a69485470696b4a4d32354a4d78497a706938544d68744b716879546f68444b6e78497a7077396c59365a55703045556e` |
| **2 Hex→ASCII** | `4LGB5RwZmLGAmRwZ4ZQBkRGZiHTpikJM25JMxIzpi8TMhtKqhyTohDKnxIzpw9lY6ZUp0EUn` |
| **3 ROT13** | `4YTO5EjMzYTNzEjM4MDOxETMvUGcvxWZ25WZkVmcv8GZugXdulGbuQXakVmcj9yL6MHc0RHa` |
| **4 再反转** | `aHR0cHM6Ly9jcmVkaXQubGludXguZG8vcmVkZW52ZWxvcGUvMTExODM4MjEzNTYzMjE5OTY4` |
| **5 Base64** | **`https://credit.linux.do/redenvelope/111838213563219968`** |

注意第 4 步的结果：`aHR0cHM6Ly9jcmVkaXQubGludXguZG8v…`

**`aHR0cHM6Ly9` 就是 `https://` 的 Base64。** 一眼就能认出。

而第 5 步解出来的结果以 `https://` 开头 —— **这就验证了前面每一步都是对的**。

## 校验口径

这是整件事的方法论核心：

> **每层都要输出中间结果，便于核对。**
>
> 最终结果若不以 `https://` 开头，说明前面某步出错，需回退排查。

拆开看是两条规则：

**规则一：每一层都要可见。** 不能只给最终答案。因为只有中间结果可核对，"对了"才是有依据的。

**规则二：终点有明确的格式约束。** `https://` 开头是一个**硬判据**。如果解出来不是，说明链路里有一层做错了 —— 而不是"可能答案就是这样"。

第二条特别重要。它把"我解出来了"变成了一个**可证伪的断言**：

- 解出来是 `https://credit.linux.do/redenvelope/…` → 对
- 解出来是别的 → **一定有一层错了**，回去查

**没有中间地带。**

## 一行命令验证

```bash
python -c "
import codecs,binascii,base64
s='<密文>'
r=s[::-1];                        print('1 反转 :',r)
a=binascii.unhexlify(r).decode(); print('2 Hex  :',a)
t=codecs.encode(a,'rot13');       print('3 ROT13:',t)
v=t[::-1];                        print('4 反转 :',v)
print('5 B64  :',base64.b64decode(v+'='*((4-len(v)%4)%4)).decode())
"
```

注意最后那个补 padding 的写法：

```python
v + '=' * ((4 - len(v) % 4) % 4)
```

Base64 的长度必须是 4 的倍数，不够要补 `=`。**这个细节如果漏了，会报 `binascii.Error: Invalid base64-encoded string`。**

## 环境约束：不要试图绕过防护

`AGENTS.md` 里有一节专门写环境：

| 项 | 说明 |
|---|---|
| 操作系统 | Windows，命令经 **Git Bash** 执行 |
| 目录切换 | 必须写成 `cd "<项目根>/linux.do"`（反斜杠 + `cd /d` 会报 `too many arguments`） |
| 运行时 | Python 3.11.0、Node v24.19.0 |
| 站点防护 | 整站位于 **Cloudflare** 之后 |

关键约束：

> 未携带浏览器会话的 `curl` / `wget` 直连 `credit.linux.do`、`linux.do`
> 一律返回 `403` + `Just a moment...` 挑战页。

于是规则很明确：

> **不要尝试用 `curl` 抓取红包页面**，也不要联网搜索题目。
> 解密所需素材（密文、截图）由用户提供，本代理只负责**解码与验证**。

这条规则的意义超出这个项目本身。

**它划了一条边界：不为了完成任务而绕过安全机制。**

Cloudflare 的挑战页是站点有意的防护。用 curl 硬闯、找绕过办法、或者去搜索别人的答案 —— 这些都超出了"解题"的范围。

**边界写进规则，而不是靠临场判断。**

## 工作约定

```
- 收到新密文后，按第 3 节的链条逐步解码，逐层列出中间结果，最后给出完整链接
- 输出最终答案时，单独用代码块给出可直接点击/复制的完整 URL
- 禁止批量删除文件
- 不得读取 .env 等密钥文件；确需出现的敏感值一律写占位符
- 不联网搜索题目、不臆测答案；素材以用户提供的为准
```

最后一条是出题人要求的直接落实：**不臆测。**

## 回头看

这个项目很小。但它是我所有项目里**方法论最纯粹**的一个。

因为它只做一件事，而且做得很干净：

> **每一层都可核对，终点有硬判据。**

这两条其实适用于所有调试工作：

- **不要只看最终结果。** 中间状态可见，才知道哪一步偏了
- **终点要有可证伪的判据。** "看起来对"不是判据；"必须以 `https://` 开头"才是

而"不要猜答案"这条要求，翻译成工程语言就是：

> **不要用"结果看起来合理"来代替"过程可以复现"。**
